# 기능 동작과 예외 상황

> **📖 작성 가이드**
>
> **이 문서의 목적**
>
> 기능이 시작되는 조건과 처리 결과를 정하고, 예상과 다른 상황에서도 서비스가 어떻게 행동할지 합의합니다.
>
> **1. 정상 동작 규칙**
>
> 핵심 기능마다 **시작 조건 → 검사할 조건 → 처리 주체 → 결과** 순서로 작성합니다. 사용자 행동이 시작점인지, 화면 진입이나 데이터 변경이 시작점인지 구분합니다.
>
> 화면에서 즉시 처리하는 일과 서버에 요청해야 하는 일을 나눕니다. 여러 사람이 같은 문장을 읽고도 서로 다른 동작을 구현할 수 있다면 규칙을 더 구체적으로 적어야 합니다.
>
> **2. 입력과 검증**
>
> **검증**은 입력값이 약속한 형식에 맞는지 확인하는 과정입니다.
>
> | 확인할 항목 | 결정할 내용 |
> | --- | --- |
> | 필수 여부 | 값을 비워둘 수 있는지 |
> | 형식과 제한 | 허용하는 값의 종류, 길이, 개수 |
> | 안내 위치 | 잘못된 입력을 어디에서 알려줄지 |
> | 최종 판단 | 화면과 서버 중 어디에서 확정할지 |
>
> 화면의 검증은 사용자가 빠르게 수정하도록 돕고, 서버의 검증은 저장할 값을 최종 확인합니다.
>
> **3. 예외와 복구**
>
> 빈 결과, 중복 클릭, 네트워크 단절, 처리 실패가 생겼을 때 **현재 데이터가 유지되는지**, **재시도가 가능한지**, **어느 화면으로 돌아가는지** 정합니다.
>
> **핵심:** 오류 메시지는 문제를 알리는 데서 끝나지 않고 다음 행동을 안내해야 합니다.

## 1. 정상 동작 규칙

### 1-1. 기능별 동작 규칙

시작점은 세 가지로 구분합니다.

- **[행동]**: 사용자가 버튼을 누르는 등 직접 행동해서 시작됩니다.
- **[진입]**: 화면에 들어오는 것만으로 시작됩니다.
- **[변경]**: 서버의 데이터나 상태가 바뀌어서 시작됩니다.

| 기능 | 시작점 | 검사할 조건 | 처리 주체 | 결과 |
| --- | --- | --- | --- | --- |
| 첫 화면 | [진입] 서비스 주소 접속, 없는 주소 | 없음 | 화면 | 물품 목록을 보여 줍니다. 로그인하지 않아도 됩니다. |
| 회원가입 | [행동] "회원가입" 클릭 | 입력 규칙(2장), 이메일 중복 | 화면 검사 → 서버 저장 | "회원가입이 완료되었습니다. 로그인해주세요." → 이메일이 채워진 로그인 화면. 자동으로 로그인하지 않습니다. |
| 로그인 | [행동] "로그인" 클릭 | 빈 칸, 이메일·비밀번호 일치 | 화면 검사 → 서버 확인·토큰 발급 | 서버가 발급한 JWT 토큰(accessToken)과 사용자 정보(id, 이름, 이메일)를 저장하고 원래 하려던 화면으로 이동. 없으면 마이페이지 |
| 로그아웃 | [행동] "로그아웃" 클릭 | 없음 | 화면 (서버 요청 없음) | 토큰과 사용자 정보를 지우고 물품 목록(첫 화면)으로 이동 |
| 회원 전용 화면 보호 | [진입] 등록·수정·마이페이지 화면 | 토큰이 있는지 | 화면 | 토큰이 없으면 "로그인이 필요한 기능입니다." → 로그인 화면 (돌아올 주소 기억) |
| 물품 목록·검색 | [진입] 목록 화면, [행동] "검색" 클릭 | 검색어 100자 이하 | 서버 | 조건에 맞는 물품을 등록 일시(createdAt) 최신순으로 20개씩 표시 |
| 물품 상세 | [진입] 카드 클릭 또는 주소 입력 | 물품이 있는지, 토큰이 있는지 | 서버 | 상세 정보와 작성자 이름 표시. 토큰이 있으면 작성자 연락처 표시, 없으면 서버가 연락처를 null로 보내고 화면은 로그인 안내 표시. 로그인한 사용자가 작성자면 "수정"·"삭제" 버튼 표시 |
| 물품 등록 | [행동] "등록하기" 클릭 | 로그인, 입력 규칙(습득물이면 보관 장소 필수), 본인이 올린 사진 | 화면 검사 → 서버 저장 | 등록한 물품의 상세 화면으로 이동 |
| 물품 수정 | [진입] 수정 화면, [행동] "수정하기" 클릭 | 작성자인지, 입력 규칙 | 화면 검사 → 서버 저장 | 진입 시 작성자가 아니면 수정 화면 대신 안내. 저장되면 상세 화면에 바뀐 내용 표시 |
| 상태 변경 (해결 완료) | [행동] 수정 화면에서 상태를 "해결 완료"로 바꾸고 "수정하기" 클릭 | 작성자인지, 상태 값(OPEN/RESOLVED) | 화면 → 서버 저장 | 상세·목록에 "해결 완료" 표시. 물건 전달이 끝난 뒤 작성자가 바꿉니다(1-4). |
| 물품 삭제 | [행동] "삭제" → 확인창 "확인" | 작성자인지 | 화면 확인창 → 서버 삭제 | "삭제되었습니다." → 마이페이지 |
| 마이페이지 | [진입] 마이페이지 화면 | 로그인 | 서버 | 내 정보, 등록한 습득물·분실물 개수, 내가 등록한 물품 목록 |
| 로그인 만료 처리 | [변경] 서버가 "로그인 만료"(401)로 응답 | - | 서버 판단 → 화면 처리 | 토큰을 지우고 작성 중인 입력값을 임시 보관 → 로그인 화면 → 로그인 후 원래 화면에서 입력값 복원 |
| 올리기만 한 사진 정리 | [변경] 사진을 올린 지 3시간이 지남 | 어떤 물품의 사진 주소(image_url)에도 연결되지 않았는지 | 서버 | 사진 파일과 업로드 기록을 삭제 |

### 1-2. 화면에서 즉시 처리하는 일과 서버에 요청하는 일

| 화면에서 즉시 처리 (서버에 묻지 않음) | 서버에 요청 (서버가 결정) |
| --- | --- |
| 입력 형식 검사 (빈 칸, 글자 수, 이메일 형식, 전화번호 형식, 미래 날짜, 사진 형식·크기) | 입력값 최종 검증 |
| 비밀번호 확인 칸 일치 검사 | 이메일 중복 확인, 회원 저장 |
| 토큰이 있는지로 회원 전용 화면 막기 | 로그인 (비밀번호 확인, JWT 토큰 발급) |
| 작성자인지로 수정·삭제 버튼 보이기/숨기기 | 토큰이 진짜인지, 만료됐는지 확인 |
| 처리 중 버튼 잠금과 "~ 중..." 표시 | 작성자 확인 후 수정·삭제·상태 변경 실행 |
| 사진 미리보기 | 사진이 실제 이미지인지 확인하고 저장 |
| 로그아웃 (토큰 삭제) | 검색, 정렬(등록 일시 기준), 20개씩 나누기 |
| 삭제 확인창, 취소, 뒤로 가기 | 물품 번호, 작성자, 상태, 등록 일시 지정 |
| 검색 조건과 작성 중인 입력값 보관 | 상태 값(OPEN/RESOLVED) 확인 |
| 구분에 따라 보관 장소 칸 보이기/숨기기 (습득물만 표시) | 습득물이면 보관 장소가 있는지 검사 |
| 값이 없는 선택 항목 숨기기, 사진이 없으면 기본 이미지 | 토큰이 없으면 작성자 연락처를 null로 보냄 |
| 비회원에게 연락처 대신 로그인 안내 표시 | 글에 연결되지 않은 사진 3시간 뒤 삭제, 물품 삭제·사진 교체 시 예전 사진 삭제 |

**양쪽에서 하는 일은 화면이 안내하고 서버가 확정합니다.** 예를 들어 수정·삭제 버튼은 화면이 작성자에게만 보여 줍니다. 하지만 실제로 수정·삭제할 수 있는지는 서버가 작성자를 확인해서 정합니다. 보관 장소도 같습니다. 칸을 보여 줄지는 화면이 정하고, 습득물에 보관 장소가 있는지는 서버도 확인합니다.

### 1-3. 헷갈리기 쉬운 규칙

여러 사람이 다르게 구현할 수 있는 문장은 아래처럼 구현합니다.

| 문장 | 이렇게 구현합니다 |
| --- | --- |
| "첫 화면" | 서비스 주소와 없는 주소는 물품 목록으로 보냅니다. 로그인 화면은 헤더의 "로그인"을 누르거나 로그인이 필요한 기능을 쓸 때만 엽니다. |
| "최근 등록한 순서" (정렬 날짜) | 목록 정렬에 쓰는 날짜는 등록 일시(`createdAt`)입니다. 최신순·오래된 순 모두 `createdAt` 기준입니다. 분실·습득 날짜(`lostFoundAt`)로 정렬하면 최근 올린 글이 아래로 묻히고 같은 날짜 글의 순서가 흔들려서 쓰지 않습니다. '찾는 중'을 위로 올리지 않고, 미해결 물품만 보려면 상태 필터를 씁니다. |
| "검색어가 들어 있는 물품" | 앞뒤 공백을 지운 검색어가 이름, 설명, 장소, 보관 장소 중 하나에 들어 있으면 결과에 넣습니다. 영문 대소문자는 구분하지 않습니다. 검색어가 비어 있으면 전체 목록을 보여 줍니다. |
| "20개씩" | 목록 맨 아래의 "더 보기" 버튼으로 다음 20개를 이어 붙입니다. 마지막까지 불러왔으면 버튼을 숨깁니다. |
| "검색 조건이 그대로 남은 목록" | 검색어, 구분, 상태, 정렬을 주소(예: `/home?keyword=지갑&type=FOUND`)에 담아, 뒤로 가기와 새로고침에도 유지합니다. |
| "원래 하려던 화면" | 로그인 화면으로 보내기 직전의 주소입니다. 그 주소가 없거나 로그인·회원가입 화면이면 마이페이지로 갑니다. 헤더의 "로그인"을 눌러 직접 들어온 경우에도 마이페이지로 갑니다. |
| "이메일" | 앞뒤 공백을 지우고 소문자로 바꿔서 보냅니다. `Test@a.com`과 `test@a.com`은 같은 계정입니다. |
| "전화번호" | 회원가입의 선택 항목입니다. 입력했다면 `010-0000-0000` 형식이어야 합니다. 비워 두면 전화번호 없이 가입하고, 화면 어디에도 전화번호 칸을 표시하지 않습니다. 입력한 전화번호는 내가 올린 게시물의 작성자 연락처로 쓰입니다. |
| "작성자 연락처" | 게시물 작성자의 전화번호입니다. 로그인한 사용자에게만 보여 줍니다. 토큰 없이 상세를 조회하면 서버가 `userPhone`을 `null`로 보내고, 화면은 연락처 자리에 "로그인하면 작성자 연락처를 볼 수 있습니다."를 표시합니다. 로그인했는데 작성자가 전화번호를 입력하지 않았으면 연락처 칸을 표시하지 않습니다. |
| "값이 없는 칸" | 값이 없는 선택 항목(보관 장소, 전화번호, 작성자 연락처)은 칸 자체를 표시하지 않습니다. 사진만 예외로, 없으면 기본 이미지를 보여 줍니다. |
| "글자 수" | 앞뒤 공백을 지운 뒤 셉니다. 공백만 입력하면 빈 칸으로 봅니다. 비밀번호는 공백을 지우지 않습니다. |
| "날짜" | 물건을 잃어버리거나 주운 날짜(`lostFoundAt`)입니다. 오늘 날짜로 미리 채우고, 오늘 이후 날짜는 고를 수 없습니다. 목록 정렬에는 쓰지 않습니다. |
| "보관 장소" | 습득물만 입력하며, 습득물이면 필수입니다. 구분을 분실물로 바꾸면 칸을 숨기고 값을 비워 보내지 않습니다. 분실물 상세 화면에도 보관 장소를 표시하지 않습니다. 칸 표시는 프론트엔드가 하고, 습득물의 필수 검사는 화면과 서버가 함께 합니다. DB는 분실물과 같은 테이블이라 빈 값(NULL)을 허용합니다. |
| "사진" | 한 장만, 파일로만 올립니다. 이미지 주소 직접 입력은 받지 않습니다. 서버가 직접 올린 사진만 허용하기 때문입니다. 새 사진을 고르면 기존 사진을 바꾸고, "사진 빼기"로 지울 수 있습니다. 물품을 삭제하거나 사진을 바꾸면 예전 사진 파일도 서버가 지웁니다. 사진만 올리고 글을 등록하지 않으면 3시간 뒤 자동으로 지웁니다. |
| "수정하기" | 화면의 모든 항목을 한 번에 저장합니다. 선택 항목을 비우고 저장하면 기존 값도 지워집니다. |
| "해결 완료" | 물건이 주인에게 전달됐다는 뜻의 게시물 상태입니다. 소유 확인이나 물건 전달 자체가 아니라, 그 뒤에 작성자가 바꾸는 값입니다(1-4). |
| "같은 물건의 분실물 글과 습득물 글" | 첫 버전은 서로 연결하지 않습니다. 물건이 돌아간 뒤 두 글의 작성자가 각자 '해결 완료'로 바꿉니다. |
| "가입 대상" | 첫 버전은 학생인지 확인하지 않고 누구나 가입합니다. 실제 학교에서 운영할 때 학교 이메일 제한이나 이메일 인증을 검토합니다. |
| "삭제" | 되돌릴 수 없습니다. 확인창에 "삭제하면 되돌릴 수 없습니다."를 함께 적습니다. |
| "로그아웃" | 서버에 요청하지 않고 브라우저에 저장된 토큰과 사용자 정보만 지운 뒤 물품 목록으로 이동합니다. |

### 1-4. 소유 확인·물건 전달·해결 완료 구분

세 단계는 서로 다른 일입니다. 첫 버전에서 서비스가 처리하는 것은 '해결 완료' 하나이고, 소유 확인과 물건 전달은 보관 장소에서 직접 하거나 작성자에게 연락해서 사람이 합니다.

| 단계 | 뜻 | 누가 | 프론트엔드 | 백엔드 | DB |
| --- | --- | --- | --- | --- | --- |
| 소유 확인 | 찾으러 온 학생이 실제 주인인지 확인 | 보관 장소 담당자, 습득자 또는 작성자 (서비스 밖. 보관 장소에서 직접 확인하거나, 작성자에게 연락해 특징 확인) | 상세 화면에 보관 장소(습득물만)와 작성자 연락처(로그인한 사용자만)를 보여 줌 | 토큰이 없으면 작성자 연락처를 null로 보냄. 확인 자체는 처리하지 않음 | 저장하지 않음 (연락처는 members.phone) |
| 물건 전달 | 확인된 주인에게 물건을 넘겨줌 | 보관 장소에서 받아 가거나, 작성자와 약속해서 받음 (서비스 밖) | - | 처리하지 않음 | 저장하지 않음 |
| 해결 완료 | 게시물을 '해결 완료'로 바꿔 더 이상 찾는 물품이 아님을 알림 | 게시물 작성자 | 작성자에게만 "수정" 버튼과 상태 선택을 보여 줌. 목록·상세에 "해결 완료" 표시 | 토큰 확인 → 작성자인지 확인(아니면 403) → 상태 값이 OPEN/RESOLVED인지 확인 → 저장 | `items.status`를 `RESOLVED`로 바꿈 (행은 지우지 않음) |

- 습득물 게시물은 습득자가 작성자입니다. 보관 장소에 맡겨 두었다면 보관 장소에서 반환됐는지 확인한 뒤 해결 완료로 바꿉니다.
- 분실물 게시물은 분실자가 작성자입니다. 물건을 되찾으면 직접 해결 완료로 바꿉니다.
- 같은 물건의 분실물 글과 습득물 글은 연결하지 않으므로, 두 글의 작성자가 각자 해결 완료로 바꿉니다.
- 첫 버전은 누가 언제 물건을 받아 갔는지 기록하지 않습니다.

## 2. 입력과 검증

### 공통 규칙

- **안내 시점:** 입력 칸을 벗어날 때 그 칸을 검사하고, 버튼을 누를 때 전체를 다시 검사합니다. 오류가 있으면 요청을 보내지 않고 첫 번째 오류 칸으로 이동합니다.
- **안내 위치:** 칸 하나의 문제는 그 칸 바로 아래에 알려 줍니다. 칸과 상관없는 문제(로그인 실패, 서버 오류)는 버튼 바로 위에 알려 줍니다.
- **최종 판단:** 모든 항목은 서버가 확정합니다. 화면 검사는 빠르게 고치도록 돕는 용도입니다. 단, 비밀번호 확인은 서버로 보내지 않으므로 화면에서 확정합니다.
- **같은 기준:** 화면과 서버는 아래 표의 기준 값을 똑같이 사용합니다.

로그인에 실패하면 버튼 위에 "이메일 또는 비밀번호가 올바르지 않습니다. 다시 입력해주세요."만 보여 줍니다. 어느 쪽이 틀렸는지는 알려 주지 않습니다. 가입된 이메일인지 다른 사람이 알아낼 수 없도록 하기 위해서입니다.

## 3. 예외와 복구

모든 오류 안내는 **무엇이 문제인지 + 무엇을 하면 되는지**를 함께 적고, 다음 행동으로 바로 가는 버튼을 붙입니다.

### 3-1. 상황별 복구

| 상황 | 현재 데이터 | 재시도 | 돌아가는 화면 | 안내 문구 [버튼] |
| --- | --- | --- | --- | --- |
| 빈 결과: 검색 결과 없음 | 검색 조건 유지 | - | 같은 목록 | "검색 결과가 없습니다. 다른 검색어로 찾아보거나 분실물로 등록해 두세요." [전체 보기] [분실물 등록하기] |
| 빈 결과: 등록된 물품 없음 | - | - | 같은 목록 | "아직 등록된 물품이 없습니다. 첫 물품을 등록해 보세요." [습득물 등록하기] [분실물 등록하기] |
| 빈 결과: 내가 등록한 물품 없음 | - | - | 마이페이지 | "아직 등록한 물품이 없습니다." [물품 등록하기] |
| 중복 클릭 | 입력 유지 | 필요 없음 (첫 요청만 보냄) | 같은 화면 | 버튼을 "~ 중..."으로 바꾸고 잠급니다. 성공하면 다음 화면으로 **바꿔서** 이동해, 뒤로 가기로 같은 요청이 다시 가지 않게 합니다. |
| 연결 실패: 조회 (목록·상세·마이페이지) | 이미 보이는 내용 유지 | 가능 | 같은 화면 | "OO을 불러오지 못했습니다. 연결을 확인하고 다시 시도해주세요." (OO: 물품 목록, 물품 정보, 내 물품) [다시 시도] |

| 연결 실패: 회원가입·로그인 | 입력 유지 | 가능 | 같은 화면 | "서버에 연결할 수 없습니다. 잠시 후 다시 시도해주세요." [다시 시도] |

변경 요청은 서버에 이미 저장된 뒤 연결이 끊겼을 수 있습니다. 바로 다시 보내면 같은 물품이 두 번 등록될 수 있으므로, 마이페이지에서 먼저 확인하도록 안내합니다.

### 3-3. 안내 문구 모음

모든 문서와 화면은 아래 문구를 그대로 사용합니다. 문구를 바꿀 때는 이 표를 먼저 고치고, 다른 문서도 함께 고칩니다.

**문구 규칙**

- "문제 + 다음 행동" 두 문장으로 씁니다. 다음 행동은 문장이나 버튼으로 알려 줍니다.
- 숫자와 형식(5MB, JPG/PNG, 글자 수)은 서버 규칙과 같게 씁니다.
- 처리 중에는 버튼이나 내용 자리에 "~ 중..."으로 표시합니다.
