# 프론트엔드·백엔드 데이터 흐름

> **📖 작성 가이드**
>
> **이 문서의 목적**
>
> 사용자 행동 하나가 화면에서 시작해 서버와 DB를 거친 뒤 다시 화면에 반영되는 과정을 연결합니다.
>
> **1. 핵심 기능 하나를 선택하기**
>
> 처음부터 모든 흐름을 그리지 않습니다. 첫 버전에서 가장 중요한 행동을 하나 고르고, 그 행동에 필요한 입력과 결과를 끝까지 추적합니다.
>
> ```
> 사용자가 습득물 등록 선택
> ↓
> 습득물 정보 입력
> ↓
> 프론트엔드의 입력 확인
> ↓
> 등록 API 요청
> ↓
> 백엔드의 검증과 처리
> ↓
> DB에 습득물 정보 저장
> ↓
> API 응답
> ↓
> 습득물 목록에 등록 결과 표시
> ```
>
> 이 순서에서 특정 단계가 필요 없다면 제거하고, 추가 처리가 있다면 그 위치를 표시합니다.
>
> **2. 단계별 책임 정하기**
>
> 프론트엔드는 입력화면 구현과 데이터 연동 및 결과 화면 구현을 나누어 담당합니다. 한 명은 습득물 등록 폼과 입력 확인을 맡고, 다른 한명은 API 연결과 목록, 상세 화면 반영을 맡습니다.
>
> **3. 실패 흐름도 함께 연결하기**
>
> 로딩 중 중복 요청, 잘못된 입력, 네트워크 단절, 빈 결과가 생겼을 때 어느 단계에서 멈추는지 확인합니다. 사용자가 재시도할 수 있는지, 입력한 값은 유지되는지, 화면은 어떤 안내를 보여주는지 정합니다.
>
> **핵심:** 정상적으로 성공하는 경로와 실패 후 다시 진행하는 경로가 모두 설명되어야 합니다.

---

## 이 문서의 목적

찾Go의 첫 버전 핵심 기능인 **습득물 등록**이 화면 → 서버 → DB → 화면으로 이어지는 과정을 정합니다. 습득물이 등록되어야 물건을 잃어버린 사람이 목록에서 찾을 수 있으므로, 이 흐름을 가장 먼저 완성합니다.

---

## 1. 핵심 기능: 습득물 등록

가이드의 기본 순서에 찾Go에 필요한 단계를 더하고 바꿨습니다.

- **[추가]**: 기본 순서에 없던 단계입니다.
- **[변경]**: 기본 순서와 다르게 처리하는 단계입니다.

```
① 사용자가 물품 목록(첫 화면)에서 "습득물 등록하기" 선택
↓
② [추가] 로그인 확인 — 토큰이 없으면 로그인 화면으로 갔다가 등록 화면으로 돌아옴
↓
③ 습득물 정보 입력 (보관 장소 필수 + 사진 선택)
↓
④ 프론트엔드의 입력 확인
↓
⑤ [추가] 사진 업로드 API 요청 → 사진 주소(imageUrl) 받기 ※ 사진이 있을 때만
↓
⑥ 등록 API 요청
↓
⑦ 백엔드의 검증과 처리
↓
⑧ DB에 습득물 정보 저장
↓
⑨ API 응답
↓
⑩ [변경] 등록한 습득물의 상세 화면 표시 → 목록과 마이페이지에도 반영
```

- **② 로그인 확인**: 등록은 회원만 할 수 있습니다. 토큰이 없으면 입력을 시작하기 전에 로그인 화면으로 보냅니다.
- **⑤ 사진 업로드**: 사진 파일은 물품 정보와 따로 먼저 올립니다. 백엔드가 돌려준 사진 주소를 ⑥ 등록 요청에 넣습니다.
- **⑩ 결과 표시**: 사용자가 등록한 내용을 바로 확인할 수 있도록 목록이 아니라 상세 화면으로 이동합니다.

## 2. 단계별 책임과 데이터

### 담당 나누기

| 담당 | 맡는 일 |
| --- | --- |
| **프론트엔드 A** (입력 화면) | 등록 폼, 보관 장소 칸 표시·필수 검사(습득물일 때만 보임), 사진 선택·미리보기, 입력 확인, 칸별 오류 문구 표시 |
| **프론트엔드 B** (API 연결·결과 화면) | 로그인 확인, API 요청(토큰 헤더 포함), 응답·오류 처리, 상세·목록·마이페이지 반영 |
| **백엔드** | 토큰 확인, 최종 검증(습득물이면 보관 장소 필수), 사진 저장과 정리, DB 저장, 응답 |

**A와 B가 주고받는 것:**

- A는 입력 확인을 통과한 입력값을 B의 등록 함수에 넘깁니다.
- 등록에 성공하면 B가 상세 화면으로 이동합니다.
- 실패하면 B가 오류 문구를 A에게 돌려주고, A가 그 문구를 폼에 표시합니다.

### 단계별 흐름

| # | 단계 | 담당 | 주고받는 데이터 |
| --- | --- | --- | --- |
| ① | 등록하기 선택 | A | 물품 목록(첫 화면) 버튼 → 등록 화면 (구분: 습득물로 미리 선택, 보관 장소 칸 표시) |
| ② | 로그인 확인 | B | 브라우저에 저장된 `accessToken`이 있는지 확인 |
| ③ | 정보 입력 | A | 구분, 이름, 설명, 장소, 날짜, 보관 장소(습득물이라 필수), 사진 파일(선택) |
| ④ | 입력 확인 | A | 필수 항목(구분·이름·설명·장소·날짜·보관 장소), 글자 수(이름·장소·보관 장소 100자, 설명 2000자), 미래 날짜 불가, 사진 JPG/PNG·5MB 이하. 틀리면 **요청을 보내지 않고 여기서 멈춤** |
| ⑤ | 사진 업로드 | B → 백엔드 | 요청 `POST /api/images` (파일) → 응답 `{ imageUrl }`. 백엔드는 사진을 검사하고 줄여서 저장하며, 올린 사람을 기록합니다(item_image의 filename, user_id). 3시간 안에 ⑥ 등록으로 글에 연결되지 않으면 자동으로 지웁니다. |
| ⑥ | 등록 요청 | B → 백엔드 | `POST /api/items` + `Authorization: Bearer 토큰` + 물품 정보(JSON, 아래 예시) |
| ⑦ | 검증과 처리 | 백엔드 | 토큰 확인 → 입력 규칙 검증(습득물이라 보관 장소 필수) → 본인이 올린 사진인지 확인(item_image의 user_id) → 작성자, 상태(`OPEN`), 등록 일시 지정 |
| ⑧ | 저장 | 백엔드 → DB | 물품 테이블에 한 행 추가, 물품 번호(`id`) 생성. 사진 주소는 `items.image_url`에 저장 |
| ⑨ | 응답 | 백엔드 → B | `201` + 저장된 물품 정보 (아래 예시) |
| ⑩ | 결과 표시 | B | 응답의 `id`로 상세 화면 이동. 목록과 마이페이지는 다음에 불러올 때 새 물품이 포함됨 (목록은 등록 일시 최신순이라 앞쪽에 보임) |

### 주고받는 데이터 예시

⑥ 등록 요청 (프론트엔드 → 백엔드)

```json
{
  "type": "FOUND",
  "name": "검은색 반지갑",
  "description": "가죽 반지갑이고 안에 학생증이 있습니다.",
  "location": "본관 1층 복도",
  "storageLocation": "학생부실",
  "lostFoundAt": "2026-11-05",
  "imageUrl": "/api/images/3f2a9c1e.jpg"
}
```

⑨ 응답 (백엔드 → 프론트엔드)

```json
{
  "id": 42,
  "userId": 7,
  "type": "FOUND",
  "name": "검은색 반지갑",
  "description": "가죽 반지갑이고 안에 학생증이 있습니다.",
  "status": "OPEN",
  "location": "본관 1층 복도",
  "storageLocation": "학생부실",
  "imageUrl": "/api/images/3f2a9c1e.jpg",
  "lostFoundAt": "2026-11-05",
  "createdAt": "2026-11-05T14:20:00"
}
```

- `id`, `userId`, `status`, `createdAt`은 백엔드가 정합니다. 프론트엔드는 보내지 않습니다.
- `createdAt`은 목록 정렬 기준인 등록 일시이고, `lostFoundAt`은 물건을 주운 날짜(표시용)입니다.
- `storageLocation`은 습득물이라 필수입니다. 분실물을 등록할 때는 보내지 않습니다.
- 물품 종류(`itemCategory`)는 첫 버전에서 제외해 요청에 넣지 않습니다(후속 개선).

## 3. 실패 흐름

| 상황 | 멈추는 단계 | 화면 안내 | 입력값 | 다시 진행하는 방법 |
| --- | --- | --- | --- | --- |
| 로딩 중 중복 요청 | ⑤·⑥ | 버튼을 "등록 중..."으로 바꾸고 누를 수 없게 함 | 유지 | 응답이 오면 자동으로 진행. 성공하면 상세 화면으로 바꿔 이동해서, 뒤로 가기로 다시 제출되지 않게 함 |
| 잘못된 입력 (프론트엔드에서 발견) | ④ | 해당 칸 아래 "OO을 입력해주세요." 등. 첫 번째 오류 칸으로 이동 | 유지 | 고친 뒤 "등록하기" (서버 요청 없음) |
| 잘못된 입력 (백엔드에서 발견, 400) | ⑦ | 백엔드가 보낸 오류 문구를 해당 칸 아래에 표시 | 유지 | 고친 뒤 "등록하기" |
| 사진 오류 (형식, 5MB 초과) | ④ 또는 ⑤ | "JPG/PNG, 5MB 이하 사진만 올릴 수 있습니다. 다른 사진을 선택해주세요." | 사진 외 유지 | 다른 사진을 고르거나 사진 없이 등록 |
| 로그인 만료 (401) | ⑤ 또는 ⑦ | "로그인이 만료되었습니다. 다시 로그인해주세요." 후 로그인 화면으로 이동 | 브라우저에 임시 보관 후 복원 | 로그인 → 등록 화면으로 돌아오면 입력값이 다시 채워짐 → "등록하기" |
| 네트워크 단절, 서버 응답 없음 | ⑤ 또는 ⑥ | "처리됐는지 확인하지 못했습니다. 마이페이지에서 확인한 뒤 다시 시도해주세요." [마이페이지에서 확인] [다시 시도] | 유지 | 마이페이지에서 등록됐는지 확인한 뒤 "다시 시도". 이미 받은 사진 주소는 다시 쓰고 사진은 다시 올리지 않음 (올린 지 3시간이 지났으면 사진을 다시 올림) |
| 사진만 올리고 등록하지 않음 (취소, 창 닫기) | ⑤ 이후 | - | - | 올린 사진은 글에 연결되지 않아 3시간 뒤 자동 삭제. 다시 등록할 때 사진을 다시 올림 |
| 서버 오류 (500) | ⑦·⑧ | "일시적인 문제로 처리하지 못했습니다. 잠시 후 다시 시도해주세요." [다시 시도] | 유지 | 잠시 후 "다시 시도" |
| 빈 결과 | ⑩ 이후 목록 | 물품이 없으면 "아직 등록된 물품이 없습니다. 첫 물품을 등록해 보세요." [습득물 등록하기] [분실물 등록하기]. 검색 결과가 없으면 "검색 결과가 없습니다. 다른 검색어로 찾아보거나 분실물로 등록해 두세요." [전체 보기] [분실물 등록하기] | - | 등록하거나 검색 조건을 바꿈 |

- **실패해도 입력값은 지우지 않습니다.** 사용자는 같은 화면에서 고치거나 "다시 시도"를 누르기만 하면 됩니다.
- **응답 전에 연결이 끊긴 경우**, 서버에는 이미 저장됐을 수 있습니다. 같은 물품이 두 번 등록되지 않도록 "마이페이지에서 확인" 버튼으로 먼저 확인하게 합니다.
