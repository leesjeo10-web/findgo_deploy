# 로그인 없는 프론트엔드 구현 기록

2026-11-12 사용자 요청으로 구현을 시작했다. 기존 Finder 저장소와 선배님이 제공한 디자인을 사용한다.
기획의 최종 로그인 필수 정책과 별개로 **현재 개발 단계에서는 로그인·토큰을 추가하지 말라**는 최신 지시를 따른다.

## 구현한 화면과 공유 부품

| 화면 | 주요 구성 |
| --- | --- |
| 메인 | Header 검색, HomeBanner, AccountPanel, ItemFilters, ItemGrid, ItemCard |
| 상세 | ItemImage, ItemBadges, 장소·날짜·보관 장소, 설명, 반환 안내, ItemOwnerActions, DeleteItemDialog |
| 등록·수정 | 동일한 ItemForm, FormField, ItemImageInput, ItemPreview·ItemCard |
| 내 물품 | 전체 개수 MyItemSummary, 구분·상태 필터, MyItemList의 행 배치 |

새 JSX를 필요한 역할에만 추가했다. 작은 제목·문단마다 파일을 만들지 않았다.
기존 ItemStatusBadge는 ItemBadges 안에서 사용하며 ItemOwnerActions도 구현해 활용했다.
FormField·Button·LoadingState·EmptyState·ErrorState·LoadMoreButton·ConfirmDialog·Toast·레이아웃을 여러 화면에서 공유한다.
텍스트 입력은 현재 기본 HTML 요소와 공통 스타일을 사용하고, 별도 TextInput·Dialog 파일은 아직 필요하지 않아 추가하지 않았다.

## 저장과 동작 범위

- 실제 데이터를 브라우저 IndexedDB에 저장한다. 메모리 변수로 성공을 꾸미거나 임의 지연 후 성공으로 표시하지 않는다.
- 사진은 Blob으로 항목과 함께 저장한다. 5MB 사진을 localStorage 문자열로 넣는 방식을 사용하지 않는다.
- 등록·수정·삭제는 트랜잭션 완료 후 성공으로 표시한다. 사진 교체·제거도 같은 항목 저장에 포함된다.
- 같은 제출 id를 재시도하면 한 건만 등록하도록 브라우저 저장 구현에서 처리한다. 실제 서버의 중복 방지 계약을 확정한 것은 아니다.
- 목록은 검색·구분·상태·정렬을 적용한 뒤 20개씩 반환하고, 내 물품 전체 개수는 현재 페이지의 길이와 별도로 계산한다.
- JPG/PNG만 받고 MIME·파일 헤더·용량·브라우저 이미지 해독을 확인한다. 다른 형식 변환은 하지 않는다.
- 폼 실패 때 다른 입력값을 유지한다. 잘못된 사진으로 기존 사진을 바꾸지 않는다.
- 목록 조건을 URL에 보관하고 상세에서 돌아갈 때 유지한다. 미리보기는 폼 값을 공유한다.
- 초기 샘플·가짜 계정·작성자 전화번호를 자동 생성하지 않는다.

이번 버전의 모든 물품은 같은 브라우저에서 작성한 항목이다. 여러 사람의 공유 DB, 실제 작성자 판별, 다른 기기 동기화는 아직 없다.

## 보류한 내용

- 로그인·회원가입·토큰 발급/저장/인증 헤더·로그인 상태·화면 보호.
- 계정 프로필·전화번호 편집·비밀번호 변경·학생 관리자 화면.
- 계정 연락처 존재 검사와 사진 조회 인증. 최종 기획을 삭제한 것이 아니라 계정 연결과 함께 구현할 부분이다.
- 번호 삭제 금지, 관리자 번호 예외, 3시간 미연결 사진 정리 등 미확정 정책.
- 실제 HTTP API·백엔드 변경·Notion 수정·배포·커밋·푸시.

현재 내 물품 화면에는 가짜 이름·아이디를 넣는 대신 내가 등록한 항목과 전체 개수를 표시한다.
원래 로그인 패널 자리도 등록·내 물품 바로가기로 사용한다. 계정 기능 구현 시 원래 디자인의 인증 상태를 연결한다.

## 검증

### 자동 테스트: 16개 통과

Node 기본 테스트 실행기와 [fake-indexeddb](https://github.com/dumbmatter/fakeIndexedDB)를 사용한다.
테스트는 Node 프로세스의 별도 메모리 DB에서 실행해 사용자의 브라우저 데이터에 접근하지 않는다.

- 습득물 보관 장소 필수·분실물 전환 시 값 제거.
- 공백·글자 수 경계·미래/잘못된 날짜.
- 검색 대상·구분/상태 조합·등록일 정렬·20건 이후 페이지.
- 형식·5MB 제한·MIME만 이미지인 잘못된 파일.
- 등록/재조회·사진 Blob 보관·동일 제출 중복 방지.
- 수정 시 id·등록일 보존, 상태·사진 제거 반영.
- 삭제 후 항목·사진·집계에서 제거, 없는 항목 처리.
- 전체 개수와 페이지/필터 개수 분리.
- 트랜잭션 중단 시 변경 취소.

### 실제 브라우저에서 확인

- 빈 목록·등록 필수 입력 오류·입력한 값을 반영하는 카드 미리보기.
- 습득물 등록 → 상세 이동 → 새로고침 후 정보 유지.
- 정상 PNG 첨부 → 수정 저장 → 해결 완료 → 새로고침 뒤 사진 표시.
- 내 물품 전체 개수와 상태 필터 결과 개수의 분리.
- 분실물로 선택하면 보관 장소 숨김, 분실물 등록·상세.
- 검색어·상태 조합, 상세에서 목록으로 돌아갈 때 URL 조건 유지.
- 삭제 확인창 열기·취소 시 항목 유지. 실제 삭제 저장은 위 자동 테스트에서 검증.
- 데스크톱(1440px)과 모바일(390px) 메인 배치, 사진 표시.

최종 자동 테스트 16개·배포 빌드·git diff --check를 통과했다. 인증 폴더의 기존 파일은 변경하지 않았고 기존 파일 삭제도 없음을 확인했다.

5MB 초과 첨부의 브라우저 자동 선택은 도구 오류로 완료하지 못해 자동 테스트로 검증했다.
JPG 첨부·드래그 앤 드롭·20건 이후 더 보기의 실제 브라우저 조작은 별도 검증하지 않았고, 관련 입력/목록 로직은 자동 테스트 범위다.
실제 백엔드·계정·권한·연락처 공개·보안·다른 기기 저장 동작은 검증하지 않았다.

npm test와 npm run build로 다시 확인할 수 있다.
