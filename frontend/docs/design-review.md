# 찾Go 디자인 파일 검토

이 문서는 2026-11-11 검토 기록이다. 아래의 당시 미정 사항과 비회원 규칙은 [2026-11-12 최신 기획 검토](spec-review-2026-11-12.md)·[현재 구조안](frontend-structure.md)·사용자 답변으로 대체해서 읽는다. 초기 비밀번호 변경·연락처 편집·관리자 기능은 새 기획에 포함됐다.

## 이번 작업 범위

디자인 원본은 /Users/gimbeomgyu/Downloads/chatgo-design/이다.
HTML 6개와 CSS·스크립트, 로고·폰트·일러스트를 읽고 개인 Notion 문서 9개를 다시 조회했다.
이번 결과물은 [컴포넌트·폴더 구조안](frontend-structure.md)과 이 검토 기록이다.

원본 디자인, JSX·CSS·설정·API, Notion 문서는 수정하지 않았다. 기존 컴포넌트 뼈대도 보존했다.
브라우저 미리보기는 로컬 서버 실행 권한과 파일 URL 정책 제한으로 수행하지 못했다. 따라서 렌더링·반응형 동작 검증을 통과했다고 주장하지 않으며, 아래 판단은 HTML/CSS/스크립트와 이미지 원본 검토에 근거한다.

개별 5개 HTML은 초록색·Paperlogy·서비스 로고로 공통 규칙이 맞아 있고, 학교 지급 계정 안내가 있다.
이번에는 이를 구현 기준으로 선택했다. 수정 디자인을 받으면 기준과 구조안을 갱신한다.

### 공통 시각 규칙

- 주 색상: #039855, #12B76A, #32D583 / 분실물 강조 #EF6820.
- 본문·보조 글자: #141A17, #5E6C65 / 테두리 #E2E8E4, #CDD6D1.
- 폰트: Paperlogy 400·500·600·700·800.
- 컨트롤 모서리: 10px. 큰 영역은 화면에 따라 16px 또는 20px이므로 하나로 강제 통일하지 않는다.
- 각 HTML에 겹쳐 들어 있는 폰트·색상·기본 입력·버튼 규칙은 공통 스타일로 추출한다.
- 같은 .hero, .page, .field 이름이 서로 다른 화면에서 쓰인다. 공통 규칙과 화면 전용 스타일을 구분해 충돌을 막는다.
- 반응형·움직임 감소용 CSS가 있지만, 실제 크기별 렌더링은 구현 단계에서 확인한다.

## 노션과 최신 계획 대조

조회 범위는 사용자가 지정한 [개인 복사본](https://app.notion.com/p/40f4e52d239780e48751d9710e8bed30)의 서비스 개요·기능·이용 흐름·예외·테스트·개발 설계·기술 스택·API다.
공동 원본과 초기 체크리스트는 이번 검토 대상에서 제외했다.

- 이전에 개인 문서에 반영한 필드·전화번호 표기, 테스트 확장, 미연결 사진·재시도·집계의 미확정 표시를 확인했다.
- 개인 Notion에는 아직 이메일 로그인·회원가입과 가입 시 전화번호 수집 설명이 남아 있다.
- 사용자 최신 결정은 [학번 로그인·학년별 계정 지급·회원가입 제외·JWT 유지](decisions.md)다. 구현 기준은 이 최신 결정을 우선한다.
- 아이디 입력의 username 속성이나 8자리 예시는 시안의 값이다. 실제 로그인 요청 필드·학번 형식으로 확정하지 않는다.
- 사진 JPG/PNG·5MB·1장, 습득물 보관 장소, 작성자 권한, 공개 조회와 연락처 조건은 문서와 대조하되 미확정 정책을 구현 완료로 간주하지 않는다.

| 로그인 필요 화면 | 기획은 로그인 후 복귀를 설명하고, 시안은 안내 카드·로그인 링크를 보여줌 | RequireAuth 한 곳에서 이동과 복귀 정책을 정리. 자동 이동 여부는 구현 전 확인 |

## 시안에서 그대로 옮기지 않을 것

- 테스트 계정·초기 비밀번호·고정 사용자와 샘플 물품 데이터.
- ‘시안 상태 보기’, 오류 응답 선택, 비회원·작성자 역할 전환 같은 확인용 도구.
- setTimeout으로 성공을 꾸미는 저장·삭제·로그인 처리, 브라우저 변수의 실패 횟수·가짜 인증 상태.
- innerHTML과 직접 이벤트 연결로 화면을 다시 만드는 전체 스크립트. React의 컴포넌트·상태·이벤트와 실제 API에 맞게 구현한다.
- 새로운 자료를 받기 전에 미정 정책을 확정해 둔 로그인·전화번호·비밀번호 API.

## 구조 설계 결과

기존 app / features / shared 구분은 계속 사용할 수 있다.
메인의 HomeBanner·AccountPanel, 등록 화면의 ItemPreview, 마이페이지의 MyItemList를 추가 후보로 정리했다.
상세의 작은 정보 섹션과 마이페이지 행은 우선 각 화면·목록 파일 안에 두고, 역할이 커질 때 추가로 분리한다.

이 문서는 검토 결과이며 실제 UI·API 구현이나 테스트 실행 결과가 아니다.
