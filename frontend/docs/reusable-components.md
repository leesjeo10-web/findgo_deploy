# 찾Go 재사용 부품 목록

2026-11-12 구조 검토에서 정한 **재사용 후보의 종류 수**다. 현재 로그인 없는 물품 기능 구현 상태는 [구현 기록](frontend-implementation.md)을 따른다.

- 공통 화면 부품 **13종** + 기능 안에서 공유할 부품 **6종** = **19종 후보**.
- 아래 19종 중 현재 15종은 실제 화면에서 사용한다. PasswordInput·PasswordChangeForm은 인증과 함께 보류했다.
- TextInput은 별도 파일 없이 공통 입력 스타일을 사용하며, Dialog도 아직 별도 파일을 만들지 않고 ConfirmDialog의 기본 dialog 요소를 사용한다.
- 표의 "뼈대 있음/새 후보"는 구현 전 분류 기록이다. 지금 실제 구현 상태를 뜻하지 않는다.

## 공통 부품 13종

| 번호 | 부품 | 공유 위치·역할 | 현재 상태 |
| --- | --- | --- | --- |
| 1 | Button | 로그인·저장·등록·수정·취소·삭제·학생 추가. 색상·크기·처리 중 표시를 옵션으로 받음 | 뼈대 있음 |
| 2 | FormField | 모든 폼의 제목·필수 표시·도움말·칸별 오류 배치 | 뼈대 있음 |
| 3 | TextInput | 아이디·이름·장소·전화번호·검색. 의미와 검사 규칙은 각 폼이 정함 | 새 후보 |
| 4 | PasswordInput | 로그인·비밀번호 변경·학생 추가·관리자 초기화 입력의 보기/숨기기 | 새 후보 |
| 5 | Dialog | 삭제 확인·비밀번호 초기화 입력창의 열기/닫기·초점·키보드 동작 | 새 후보 |
| 6 | ConfirmDialog | 물품 삭제·학생 삭제. Dialog 위에 문구·확인/취소·처리 중 상태 구성 | 뼈대 있음 |
| 7 | LoadingState | 인증 확인·목록·상세·마이페이지·학생 목록 조회 | 뼈대 있음 |
| 8 | EmptyState | 등록 물품 없음·검색 결과 없음·내 물품 없음·학생 검색 결과 없음 | 뼈대 있음 |
| 9 | ErrorState | 목록·상세·내 물품·학생 조회 실패와 다시 시도. 폼의 칸별 오류와 구분 | 뼈대 있음 |
| 10 | LoadMoreButton | 물품 목록·내 물품 목록의 다음 20개 조회 | 뼈대 있음 |
| 11 | Toast | 비밀번호·연락처 변경, 물품 삭제, 학생 관리 완료. 이동 후에도 안내 유지 | 새 후보 |
| 12 | Header | 목록·상세·등록·수정·마이페이지·관리. 관리자 메뉴·검색 영역은 조건에 따라 표시 | 뼈대 있음 |
| 13 | AppLayout | 로그인 뒤 일반 페이지의 헤더·본문 배치. 로그인·강제 변경은 별도 배치 가능 | 뼈대 있음 |

FormField는 제목·오류를 포함한 바깥 배치, TextInput은 실제 입력칸이다.
Dialog는 대화상자 동작, ConfirmDialog는 확인/취소 구조를 담당한다.
PasswordInput은 입력 스타일을 재사용하며 비밀번호를 전역 상태나 브라우저 저장소에 보관하지 않는다.

## 기능 안에서 공유할 부품 6종

| 번호 | 부품 | 공유 위치 | 현재 상태 |
| --- | --- | --- | --- |
| 14 | ItemForm | 등록 / 수정. 필드·검사를 공유하고 초기값·상태 선택·저장을 구분 | 뼈대 있음 |
| 15 | ItemImageInput | 등록 / 수정의 사진 선택·미리보기·교체·삭제 | 뼈대 있음 |
| 16 | ItemCard | 메인 목록 / 등록·수정의 ItemPreview | 뼈대 있음 |
| 17 | ItemImage | 카드 / 상세 / 미리보기 / 내 물품 행의 보호된 사진·기본 이미지·조회 실패 표시 | 새 후보 |
| 18 | ItemBadges | 목록 / 상세 / 미리보기 / 내 물품 행의 분실·습득 및 찾는 중·해결 완료 표시 | 새 후보. 기존 ItemStatusBadge 확장·통합 검토 |
| 19 | PasswordChangeForm | 첫 로그인 강제 변경 / 마이페이지 일반 변경 | 새 후보 |

사진 원본도 로그인 필요하다는 사용자 결정을 ItemImage 계획에 반영한다. 실제 이미지를 가져오는 방식은 백엔드와 맞춘다.
같은 부품을 사용해도 화면별 크기와 배치까지 같아야 하는 것은 아니다.

## 개수에 넣지 않은 것

- Footer: shared에 두지만 현재 최신 시안에서는 메인 한 곳만 확인돼 위 재사용 수에서 제외했다.
- RequireAuth / RequireAdmin: 여러 경로가 공유하지만 화면 부품이 아닌 접근 규칙이다.
- ItemFilters: 메인은 선택창, 마이페이지는 칩 형태다. 값·표시 규칙은 공유하되 배치를 억지로 통합하지 않는다.
- DeleteItemDialog: 물품 삭제의 권한·API를 연결한다. 바탕인 ConfirmDialog만 공통 부품 수에 포함했다.
- MyItemList / StudentList: 둘 다 행 목록이지만 정보와 동작이 달라 별도로 둔다.
- 입력칸 각각: 이름·장소·전화번호마다 별도 종류로 세지 않는다.
- textarea / select: 우선 기본 HTML 요소와 공통 스타일을 사용한다.
- 폰트·색상·간격·날짜 표시·검증 상수·HTTP 통신: 재사용하지만 JSX 부품 수에는 포함하지 않는다.

19개는 화면에 붙는 총 횟수가 아니다. 최종 디자인과 구현을 보며 합치거나 줄일 수 있다.
